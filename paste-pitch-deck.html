The Problem

Catalog data is messy. Risk is not.

A wrong voltage, a wrong fitting spec, a mislabeled certification — in industrial commerce these cause safety incidents, returned orders, and lost trust. This is not a copywriting problem. It is a trust problem.

📄

Heterogeneous inputs

PDF datasheets, CAD metadata, legacy ERP exports, JS-heavy supplier websites, scanned nameplates, sometimes just a part number.

🧩

Fragmented standards

ETIM, eCl@ss, UNSPSC, GS1 and manufacturer schemas all describe the same part differently. Nothing is comparable out of the box.

🎯

Zero tolerance for hallucination

Generative AI writes fluent, confident, wrong numbers. The winning system must prove what it asserts — or refuse to guess.

The Thesis
Reliability is not a feature. It is an architecture.
Never present an inferred value as a fact.

Mainstream RAG chatbots generate — they blend what they know with what they guess and call it all "the answer." PASTE inverts this: extraction only reports what is evidenced, enrichment deliberately, and loudly, marks its guesses, validation forces disputes to a human — and the whole thing is allowed to say "we don't know."

Architecture · Prove–Assert–Separate–Trace–Evaluate

Five stages. One hard rule:
extraction never fills gaps.

The sharp boundary between Stage 2 (faithful extraction) and Stage 4 (deliberate inference) is the anti-hallucination mechanism. The extractor's only job is to report what's in the source, field by field, with a citation.

1
Ingest + Layout Analysis
Content-hash every asset for idempotent re-runs. Layout-aware parsing (Unstructured / LayoutLMv3) separates tables, key-value blocks, headers — so the model reads structure, not a wall of text.
2
Extract — faithful only
VLM returns only what is evidenced in the source, cites page + bounding box, returns null for gaps. Two independent passes run for dispute detection. Output type: PROVED.
3
Normalize — deterministic, low risk
Unit conversion (PSI→bar), alias→canonical field mapping, ETIM / eCl@ss / UNSPSC taxonomy mapping. Free rules — no token money for PSI→bar.
4
Infer — deliberate, separate, loud
Enrichment agent fills gaps only from: sibling SKUs in the knowledge graph, web RAG, standards docs. Every inference tagged INFERRED, capped ≤ 0.70, with a full reason chain.
5
Validate · Route · Export
Compute conf() per field → auto-approve PROVED & high-conf → route disputes / low-conf / constraint-violations to the HITL review dashboard → export JSON-LD / GS1 CSV / PIM feed with provenance attached.

Scalability · Unit Economics

Millions of SKUs, without going broke.

A judge will ask how this scales to a whole catalog. Fewer than 5% of fields deserve a frontier model. That's the entire trick.

TIER 3 · frontier VLM
<1%
disputed / dense / ambiguous docs only — where cost belongs

⧗ Idempotent + incremental

Content-hash every asset; a re-run over a 10k-SKU catalog touches only the docs that changed. No reprocessing waste.

🧠 Knowledge-graph leverage

Infer a missing spec from a sibling SKU in the same product family — not a fresh expensive model call. Graph traversal < frontier inference.

👤 Review only exceptions

Tight routing keeps humans on a small, high-value slice — 85% auto-approval means human effort scales with anomalies, not with catalog size.
